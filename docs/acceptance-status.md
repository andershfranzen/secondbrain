## Review and extraction boundaries

Accepted proposals now retain the actual resolved item ID. New acceptances restore
source-backed extraction relationships after both endpoints resolve; rejected,
archived, superseded or erased endpoints are excluded. Exact project names in
reviewed user evidence use the same conservative linking path as automatic facts.
Meaning-changing edits do not inherit their original relationships. A dedicated
relationship-only review flow for those edits remains unimplemented.

Migration 0005 backfills known separately created legacy review items. It does not
infer old target selections or approve their original relationship context; legacy
acceptances with unknown resolution require manual inspection rather than automatic
relationship recovery. New acceptances persist these facts transactionally.

Extraction uniqueness, endpoint integrity and source evidence are validated before
projection writes. Provider chunk merging rewires duplicate endpoints, preserves
distinct thoughts sharing a quote and supports more than 100 candidates in the
complete dump. Saturated per-chunk lists split into smaller windows. Structured
validation still cannot establish semantic entailment; the live quality gates
remain open.

## Roadmap beyond the current implementation

The original proposal's later capabilities remain part of the overall roadmap:
streaming bidirectional voice with interruption, personalized resurfacing and
“where did I leave off?” quality evaluation, configurable briefings/reminders, and
optional permission-gated calendar integration. They are not implemented by the
single-input UI or by passing the Phase 1 tests. The current subscription connection
provides text inference and must not be represented as Realtime audio access.
